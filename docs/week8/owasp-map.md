# Week 8: the OWASP LLM Top 10 against this app

OWASP's list of the ten biggest risks of LLM applications (2025 edition), and for each one what this app does
about it and what it does not. This is a map of facts about the code, not a judgement of how much each gap
matters: ranking the gaps, in your own words, is mentor check four and is blank for you in `findings.md`.

| Risk | Where it shows up here | What exists | What does not |
|---|---|---|---|
| LLM01 Prompt injection | Text the agent reads (retrieved documents, tool results) and the question itself | The three layers in `app/agent/defense.py` and the 15-attack suite in `evals/injection.py`, measured with the defences off and on | The sanitizer is pattern matching, so a rephrased attack gets past it, and an innocent sentence that looks like an instruction would be cut. Nothing makes the model itself resist instructions in data. |
| LLM02 Sensitive information disclosure | Answers could repeat personal data that a document contains. The current corpus holds none. | Every tool is read-only. Answers may contain only email addresses and `http`, `https`, `ftp`, `hxxp` and `www` addresses found in the approved documents. | No redaction of personal data in answers, and no per-user authorization: whoever can ask can read anything the documents say. A bare domain or a `ws://` address passes the address check. |
| LLM03 Supply chain | Python packages and the local embedding model | Dependencies pinned to exact versions. The embedding model download is pinned to one revision and every file is hash-verified. | No vulnerability scan of the dependencies. |
| LLM04 Data and model poisoning | A false fact placed in a retrievable document (`ind-false-fact`) | The suite includes this attack so the gap is measured, not assumed. | Nothing stops it. The validator checks that an answer cites a document it retrieved, not that the document is true. The corpus is simply trusted. |
| LLM05 Improper output handling | The answer is plain text shown to a user | The validator withholds answers containing email, `http`, `https`, `ftp`, `hxxp` or `www` addresses that are not in the approved documents. | Answers are not escaped for display in a web page. A web front end would need that. |
| LLM06 Excessive agency | The agent chooses and runs tools | All tools are read-only, and their arguments are checked before a call runs (a date must be one the question states or a date tool produced, numbers must be in range, notes may not be instructions or addresses). | No tool can change anything today, so there is no approval step. Any write tool added later would need one. |
| LLM07 System prompt leakage | Direct and indirect requests to print the instructions | The validator withholds any answer that repeats 60 or more characters in a row of the system prompt, ignoring case and line breaks. The system prompt holds no secrets. | A leak that is paraphrased, or shorter than 60 characters, is not detected. |
| LLM08 Vector and embedding weaknesses | The Chroma index holds every document, and a planted document is indexed like any other | The injection suite builds a private throwaway index, so planted documents never enter the real one. | No access control per document, and nothing checks where a document came from before it is indexed. |
| LLM09 Misinformation | Wrong or invented answers | An answer must cite a retrieved document or say it does not know; the Week 6 eval set measures answer quality, with a judge that was built to be validated. | The model can still misread a document it cites. The judge has not been validated against your grading yet. |
| LLM10 Unbounded consumption | An agent that loops costs tokens and time | Week 7's four stop conditions (steps, tokens, time, repeated call) and the per-minute rate limiter. | No per-user or per-day budget. |
